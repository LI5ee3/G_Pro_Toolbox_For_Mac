## 2. 接口证据与最小方案

锁定 adb **37.0.1-15733141**，原始文件 SHA-256 `1811e253b21b12cbfda7201ebaf86c10e7ddcb5c606a7a81f7c82b4c429c2d3b`。先核验锁定摘要，再运行纯客户端 help/version。首次使用 `ANDROID_ADB_SERVER_PORT=0` 被客户端参数校验拒绝；保留日志并改用不存在的本地 Unix socket 隔离。没有为使测试通过而更换 adb。

`host-features` 未列入该二进制的 help，故不据 help 猜接口。`probe-locked-adb.py` 使用临时本地假 Unix server，记录真实锁定客户端发送 `host:version`、`host:host-features`；兼容版本 + feature 响应成功，FAIL/截断响应均退出 1。空 socket 下 `version` 仍退出 0；另外用显式 `-H 127.0.0.1 -P <空闲临时端口>` 的远端 host 模式验证 server 缺失退出 1、不自动启动。该显式 host 模式仅用于安全实验，**不是生产 argv**；没有访问现用 5038、启动 adb daemon 或枚举真实设备。结果见 `locked-adb-help.txt`、`locked-adb-version.txt`、`locked-adb-behavior.json`。

[官方 adb 客户端源码](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/client/adb_client.cpp) 和 [命令入口](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/client/commandline.cpp) 解释普通查询的版本检查/启动路径；[socket 解析](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/socket_spec.cpp) 解释显式 host 实验。访问于 2026-10-22；本机保留原文。它们是当前官方源码，**不是已证明对应锁定发行版的完整源码**。兼容响应分支由真实二进制实测；不在现用 server 上制造版本冲突或自启动故障。

方案不新造 server、USB、RSA 或进程执行栈：配置端口只定义路由，不能证明独占所有权。移除应用显式 `kill-server` 恢复循环；保留官方 adb 的启动/版本协调。主动查询仍可能启动缺失 server 或替换不兼容版本，不能称为被动只读探测或完全无 server 副作用。
