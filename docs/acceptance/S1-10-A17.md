## 原因审查

S1-02 已实际发现：Preview 退出后，独立 `com.mimonitor.toolbox.preview` 域新增 `NSWindow Frame preview`。当时失败的报告与私密前后快照保留，不改写历史为 PASS。

现有宿主用 SwiftUI `Window(id: "preview")` 且未设恢复策略。Apple 文档说明场景默认使用 `automatic` 恢复；WWDC24 明确说明窗口恢复保存退出时的尺寸/位置。AppKit 也明确将 frame autosave 存于 defaults。相关证据：

- [Scene.restorationBehavior](https://developer.apple.com/documentation/swiftui/scene/restorationbehavior(_:))：公开场景级恢复策略。
- [WWDC24：Tailor macOS windows with SwiftUI](https://developer.apple.com/videos/play/wwdc2024/10148/)：窗口状态保存和关闭恢复策略。
- [NSWindow.setFrameAutosaveName](https://developer.apple.com/documentation/appkit/nswindow/setframeautosavename(_:))：AppKit 窗口 frame 与用户 defaults 的关系。
- 本机 Xcode 27.1 / macOS SDK 27.0 的 SwiftUI swiftinterface 确认该 API 可用；部署目标 macOS 27 无需兼容分支。

源码、原失败键名/场景 ID、公开 API 语义及这一行修复后的运行结果相互印证：问题属于宿主窗口框架持久化，不是内存设备/MemoryPreferences 业务存储。没有取得私有 SwiftUI 内部调用栈，不推断未公开的实现细节。
