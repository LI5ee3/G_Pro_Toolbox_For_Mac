# S2-04 最小计划：身份与旧配置兼容

固定起点 `7fc0573`。S2-03 351 Swift、独立 Preview 与实际运行边界通过后开始。用户最新指令：**完成 S2-04 并提交后停止**；继承提交推送/验收要求，不开始 S2-05、S2-06 或 Auto，不操作真机。

## 审查结论

- AdbEndpoint 与 PresetDevice.identity 已分参，但协调器仍用 adb.ip 判断活动预设、基线、任务和延迟保存；USB 空 IP 不能成为身份。
- PresetWorker 是现有配置单一串行所有者，PresetStore.set 不抛错且旧 save 无回读；新连接登记不能声称已有原子事务。复用其同步锁/队列，不新建竞争迁移线程。
- TCP connect 当前先 ensureJars 再发布 ready，monitor 恢复会触发记忆/任务，必须先通过身份能力判定。S2-03 临时 USB 限制需替换为两种传输一致的身份判定。
- 所有旧偏好/预设任务字段原样保留；当前稳定属性不证明历史 IP 所有权。全局记忆无历史设备归属，确认前暂停副作用，不翻转保存开关。

## 最小实施

1. Domain 只增加值类型和纯解析；端点引用、稳定设备证据、设备登记 ID、PresetIdentityKey 分离。使用本次不可变会话的成功、未截断 stdout 读取 ro.serialno / ro.boot.serialno；空/占位/格式错误为未知，不按型号或 USB serial 猜同机，两个可靠属性相互矛盾为冲突。
2. 连接先有界探活与属性读取。登记只给预期值，每次接入/现有 TCP 恢复路径重新验证，不把持久登记当 ready。未知可明确普通手动控制，暂停预设/自动任务/记忆；冲突/损坏存储取消旧会话且清空执行端点，阻断全部目标写入。完整入口统一与生命周期重构仍留 S2-05/06。
3. 复用 ConnectionModel 展示身份与限制；加入最小明确确认入口，说明所选端点、证据、旧所有权及全局记忆。未确认旧所有权不沿用历史基线；多个旧所有权/别名冲突不任选一个。证据不足的人为确认只在当前会话生效，断开/重连失效，自动任务/跨会话恢复不启用。
4. 单个 connection_profile_v1 envelope 保存模式/端点、schema/revision、登记与证据来源、兼容键/旧别名及迁移摘要；启动只读。显式保存才提交。旧 saved_ip 只在明确保存 TCP:5555 时镜像，新 profile 优先；USB/非默认端口不覆盖它。
5. 提交经 PresetWorker 同一所有者：保留 saved_ip、picture_presets_v1、旧 envelope 的缺失/类型/原值，先备份与 SHA-256 回读，再确认原值未变，提交完整 envelope 并验证回读。失败不激活绑定、原数据保留；外部并发改变不覆盖；二次相同确认 no-op。备份仅真实 adapter 有文件实现，Preview 使用内存，目录/文件私密。
6. 不重写 PresetEngine 的协议、JSON 或调度语义，所有协调器预设身份比较使用同一解析兼容键。旧配置后续正常编辑不撤销绑定；所有权字段出现异常变化必须暂停并提示。人工确认不能覆盖已知冲突。
